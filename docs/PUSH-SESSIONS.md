# Push wallet sessions

Push keys are recovered through the connected wallet when the user enables rooms. This app no longer initializes from or writes decrypted keys to localStorage. A successfully recovered key removes only an identical legacy `bittrees.push.pgp.<wallet>` value. If the values differ or storage is unavailable, enabling fails and the original cache is preserved for explicit recovery. No bulk cleanup or key export occurs. A reload requires enabling again; navigation within an unchanged wallet connection can reuse the in-memory client.

The app-root account observer invalidates clients on disconnect, account, chain or connector changes, including while room views are unmounted. Initialization is deduplicated and cannot restore an old session after a reconnect. Consumers receive only guarded chat methods, never the raw SDK client or decrypted key. The provider's current account and chain are checked before and after each action, and signatures also check them before and after approval. Client/view/query scope includes a connection generation, avoiding reuse of old per-wallet room-list results after reconnecting.

Messenger and room administration share this boundary. Registry writes following Push creation use the guarded signer and a synchronous recheck immediately before POST. Existing room IDs, gate rules, roles and registry authorization remain unchanged. Member panels remount per room; late membership reads are handled as failures. Existing best-effort non-session read behavior remains a separate parity concern.

Revocation prevents new actions and use of late responses; it cannot cancel a request the SDK already sent. Users must inspect history, membership or the registry before retrying an uncertain operation. JavaScript cannot promise cryptographic erasure of all previously allocated memory. Other open tabs running an older build must be reloaded.

Validation commands: `npm run test:unit`, `npm run test:push-browser`, `npm run test:recovery-browser`, `npm run build`. Browser tests use the production session manager, wallet wrapper, hook and registry-writing helper, with isolated wallet/Push fixtures. They cover key mismatch, reload/navigation, delayed initialization, disconnect while the view is unmounted, account/chain/connector changes, late creation, registry signing races, and provider changes without an event. They do not prove live Push history, provider/network behavior or physical-device acceptance, which remain required before unifying rooms in Chat.
