# Forum subscriptions

Governance exposes an opt-in daily email digest of new discussions and a read-only public feed consumed by Bittrees Chat. Post edits and replies are not sent in this first release. Notices contain original discussion titles and links to their latest versions, without copied post bodies.

Email uses the existing Governance Redis store under `bittrees:forum-email:v1:`. Configure the server-only `FORUM_RESEND_API_KEY` (sending-only, restricted to bittrees.org), `FORUM_EMAIL_FROM=Bittrees Forum <forum@bittrees.org>` and a random `CRON_SECRET`. No email enrollment is accepted while these settings are absent. Preview deployments should leave sending unconfigured. Never reuse a Chat user session or place secrets in VITE variables.

An email address is rate limited by address and requester, receives a confirmation link, and becomes active only after an explicit confirmation POST. The standalone confirmation page contains no analytics, wallet scripts or third-party resources. The capability is carried in the URL fragment, removed from browser history on opening, and is not placed in URL queries or logs. Unsubscribe remains available without a wallet or email provider. Pending links expire; active management links allow opt-out. Subscription addresses are not published or stored on-chain.

Vercel Cron checks hourly; each subscriber is eligible at most once per 24 hours. No empty digests or pre-subscription history are mailed. A 24-hour overlap with delivered-ID deduplication catches delayed indexer arrivals; delays beyond that window require manual recovery. Each run is bounded to 30 successful deliveries and four minutes, so large backlogs can delay delivery; monitor the cron results and scale the queue for higher volume. Concurrent workers share a lease. Delivery jobs persist an exact payload and idempotency key before sending. An uncertain send older than 23 hours is blocked for operator reconciliation rather than retried beyond provider deduplication ([Resend documentation](https://resend.com/docs/dashboard/emails/idempotency-keys)). Resolve these jobs after checking provider records; do not blindly delete/retry them. Unsubscribe prevents future queued sends, though an in-flight message can still arrive.

The public `/api/forum-feed` only returns active Governance topic attestations, checks schema/community and applies existing moderator removals and flag thresholds. It fails closed if moderation or the indexer is unavailable. Bounded pagination rejects incomplete digest ranges. Chat refreshes while visible, shows unread counts, links to the forum and saves opt-in/read state per wallet on the current device. It does not send DMs, grant room membership, synchronize this preference across devices, or request browser push permissions.

Validation uses disposable Redis, synthetic email requests and browser fixtures. No real confirmation or digest is sent by release testing. End-to-end real email delivery requires an explicitly selected test recipient or a user-initiated subscription after configuration.
